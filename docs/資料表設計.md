# 鋼琴教學管理與課程推廣平台－目前資料表

| 項目 | 內容 |
| --- | --- |
| 日期 | 2026-11-01 |
| 依據 | 目前 Models 與 Alembic `001`～`025_course_chat_starters` |
| 產品規則 | PRD、SRS、User Flow |

這份文件描述現在專案實際使用的資料表。舊版 V1.2 的 30 張表草案不再作為建表依據。

所有資料表都由 Alembic 建立，網站啟動時不再自動建表。拉下新程式後先執行 `alembic -c backend/alembic.ini upgrade head`。

老師與學生共用 `courses`。學生的接洽、綁定、課表、課務申請和練習也使用下面同一組表。每筆學習資料都要能辨識所屬老師與課程，不能只靠學生查詢。

## 2. 帳號

### 2.1 users

| 欄位 | 說明 |
| --- | --- |
| `id` | UUID 主鍵 |
| `email` | 唯一 |
| `password_hash` | 密碼雜湊。Google-only 帳號可空 |
| `name` | 姓名 |
| `phone_number` | 電話，可空 |
| `birthdate` | 生日，可空 |
| `sex` | 性別，可空 |
| `role` | `teacher`、`student`、`admin` |
| `is_active` | 帳號是否可用。老師核准後才為 true |
| `auth_provider` | `password` 或 `google` |
| `created_at` | 建立時間 |

### 2.2 teacher_applications

一位老師最多一筆申請。狀態為 `pending`、`approved`、`rejected`。證明文件可空，檔案本機放 `uploads/teacher_proofs/`（共用測試站放 Supabase 私有 bucket），資料庫只存位置與檔名。

主要欄位：`user_id`、`teaching_subjects`、`teaching_experience`、`bio`、`proof_file_path`、`proof_file_name`、`status`、`review_note`、`reviewed_at`、`reviewed_by`。

### 2.3 auth_identities

保存 Google 的 `provider` 與 `provider_subject`，並連回 `users.id`。

### 2.4 teacher_profiles

`user_id` 連回 `users.id`，一位使用者一筆。老師 API 用這張表確認老師身份。所有資料表的 `teacher_id` 都是 `users.id`，不是這張表的 `id`。

老師必填的只有姓名與性別（在 `users`）；`expertise`、`short_intros`、教學縣市與區域、`target_learning`、`teaching_method`、`teaching_style`、`age`、`seniority` 都可空（Alembic `009`）。`photo_path` 是老師照片，可空；沒有照片時前端用預設圖。

## 3. 課程、接洽與綁定

### 3.1 courses

| 欄位 | 說明 |
| --- | --- |
| `id` | UUID 主鍵 |
| `teacher_id` | 授課老師，FK → `users.id` |
| `title` | 課程名稱 |
| `level` | 找課程度，可空 |
| `style` | 風格，可空 |
| `delivery_mode` | 線上或實體，可空 |
| `region` | 地區，可空 |
| `price_per_lesson` | 單堂價格，可空 |
| `time_slots` | 可洽詢時段，可空 |
| `status` | `draft`、`published`、`archived` |
| `reference_midi_path` | 這門課的一份參考 MIDI，可空 |
| `image_path` | 課程圖片，可空；沒有時前端依風格用預設圖（Alembic `009`） |
| `description` | 課程介紹，可空（Alembic `009`） |
| `created_at` | 建立時間 |

只有 `published` 可以被學生洽詢。

`reference_midi_path` 是過渡期相容欄位。課程 MIDI 新上傳會同步寫入 `reference_midis`；所有讀取端搬完後，才由後續 Migration 移除。畫面已改用作業的 MIDI（3.7、5.3），課程 MIDI 目前只剩 API。

### 3.2 reference_midis

一門課最多一筆目前使用的參考 MIDI metadata，保存 `storage_key`、原始檔名、SHA-256 與檔案大小。檔案內容本機放 `uploads/midi/`，共用測試站放 Supabase 私有 bucket。Alembic `010` 會把舊的 `courses.reference_midi_path` 回填進來；舊資料無法重算的雜湊與大小保持空白。

### 3.3 inquiry_conversations

一位學生對一門課只有一段對話。綁定前後使用同一段。

唯一條件：`student_id` + `course_id`。同時保存 `teacher_id`。

### 3.4 conversation_messages

| 欄位 | 說明 |
| --- | --- |
| `conversation_id` | FK → `inquiry_conversations.id` |
| `sender_id` | 發訊者，FK → `users.id` |
| `client_message_id` | 瀏覽器產生的訊息編號，可空。同一段對話不可重複，用來避免 WebSocket 重送變成兩筆 |
| `body` | 訊息內容 |
| `created_at` | 送出時間 |
| `read_at` | 對方已讀時間，可空 |

### 3.5 course_bindings

學生和一門課的上課資格。狀態為 `bound` 或 `unbound`。解除綁定只關閉該課的教學功能，不刪除接洽對話。

唯一條件：`student_id` + `course_id`。

### 3.6 binding_codes

`code` 唯一。一組碼只屬於一位學生、一位老師、一門課和一段接洽對話。使用後寫入 `used_at`。

### 3.7 course_join_codes

一門課最多一組限時綁定碼（`course_id` 唯一）。`code` 唯一，`expires_at` 是到期時間。期限內可重複使用；重發或停用後舊碼失效。

### 3.8 teacher_studios

一位老師一間工作室。`code` 是系統產生的編號，建立後不變。其他欄位：`name`、`owner_name`、`city`、`district`、`intro`。

## 4. 課表與課務

### 4.1 lesson_sessions

正式課表上的一堂課。`starts_at` 必須早於 `ends_at`。狀態為 `scheduled` 或 `cancelled`。

`course_id`、`teacher_id`、`student_id` 都要保存。

### 4.2 change_requests

學生提出約課、請假或調課。狀態為 `pending`、`approved`、`rejected`。

`request_type` 為 `booking`、`leave`、`reschedule`。請假和調課使用 `session_id` 指向原本的課堂。約課和調課使用 `proposed_starts_at`、`proposed_ends_at`，`availability_slot_id` 記下選的可上課時段。老師同意且時段沒被占用之後，才新增或修改 `lesson_sessions`。

### 4.3 availability_slots

老師開放的一段時間，只屬於一位老師。狀態為 `open`（可預約）、`held`（學生選了、等老師完成約課）、`booked`（已排課）。不是 `open` 時要有 `student_id` 和 `course_id`；`lesson_id` 指向排好的課；`from_weekly` 表示由每週可上課時間產生。

### 4.4 weekly_availability

老師每週固定可上課的時間（星期、當天第幾分鐘，台灣時間）。系統依此維持未來 8 週的 `availability_slots`，`generated_through` 記下已產生到哪一天。

### 4.5 recurring_lessons

老師和學生談好的固定上課時間。系統依此維持未來 8 週的 `lesson_sessions`（`recurring_lesson_id` 指回這筆），`generated_through` 記下已排到哪一天。

## 5. 作業與練習

### 5.1 practice_recordings

已綁定學生送出的一次錄音。狀態為 `pending`、`processing`、`completed`、`failed`。音檔本機放在 `uploads/practice/`（共用測試站放 Supabase），資料庫保存 `file_path`。`reference_midi_path` 記下送出當時用的參考 MIDI，老師之後換曲子，舊練習仍知道是跟哪一首比的。`assignment_id` 是交的作業，`metronome_bpm` 是錄音時開的節拍器速度，都可空。

### 5.2 practice_feedbacks

一筆錄音對應一筆回饋。`recording_id` 唯一。保存 `pitch_score`、`rhythm_score`、`feedback_text`、`score_sheet_path`（對照樂譜位置）。狀態為 `pending`、`completed`、`failed`。失敗時分數保持空白，不寫成 0。

### 5.3 assignments、assignment_materials

老師發給一位已綁定學生的作業。`kind` 為 `performance` 或 `quiz`；`quiz` 目前畫面還沒開放。保存 `title`、`description`、`due_at`、`midi_path`、`midi_filename`、`midi_bpm`、`practice_bpm`。每份教材檔在 `assignment_materials` 一列。

### 5.4 lesson_preparation_summaries

老師上課前看的練習整理，一堂課一筆（`lesson_id` 唯一），和每一筆練習回饋分開保存。

| 欄位 | 說明 |
| --- | --- |
| `lesson_id`、`course_id`、`teacher_id`、`student_id` | 這堂課與所屬老師、學生、課程 |
| `window_start` | 同一位學生、同一門課上一堂的結束時間；沒有上一堂時為空，代表從頭算 |
| `window_end` | 這一堂的開始時間 |
| `source_fingerprint` | 窗口與每筆來源錄音狀態、分數的雜湊。和現在算出的不同時，摘要會重寫 |
| `source_recording_ids` | 摘要用到的錄音編號，方便追溯 |
| `stats` | 次數、完成／失敗／分析中、平均分數；只有同一首參考曲才比較前後分數 |
| `summary_text` | 摘要本文。沒有平台紀錄時寫「沒有平台練習紀錄」，不說成學生沒練習 |
| `written_by` | `llm` 或 `rules`。沒有 LLM 金鑰或呼叫失敗時，改用統計自動產生 |
| `generated_at` | 產生時間 |

## 7. 原型資料表

下面兩張表由 Alembic `007` 建立，`teacher_id` 連到 `users.id`。只可作為之後 AI 測驗的參考，新功能不要沿用。

| 資料表 | 現況 |
| --- | --- |
| `learning_materials` | 教材上傳原型。只可作為之後 AI 測驗的出題來源，不是完整教材庫 |
| `quizzes` | 測驗原型，只有標題、題目與答案。AI 測驗流程尚未完成 |

舊的工作室綁定（`studios`、`studio_student_bindings`，和現在的 `teacher_studios` 無關）、舊洽詢（`course_inquiries`）、舊老師課表（`teacher_lesson_sessions`、`teacher_change_requests`）、另一套聊天（`conversations`、`messages`）與老師作業原型（`practice_assignments`、`practice_submissions`、`practice_evaluations`）的程式已經移除。本機資料庫若還留著這些表，不會再被讀寫，可以自行刪除。

尚未建立的正式表是可審核、可作答的 AI 測驗。之後要用 Alembic 新增，不沿用上面的原型表。
